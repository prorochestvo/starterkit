## Overview

The owner's shared agent tooling (skills, helper scripts, hooks) lives only in the private
repository `ai-cli-config`, checked out as `~/.claude` on both of the owner's hosts. A new
machine or a new person cannot start from it, and the public `pipeline` plugin already
depends on it: `plugins/pipeline/agents/engineer.md`, `plugins/pipeline/skills/new-plan`,
`complete-plan` and `working-agreement` call `~/.claude/skills/task-management/...` and
`~/.claude/bin/{model-id,second-opinion.sh,codex-limits.py}`, which exist only on the owner's
hosts.

This plan publishes the shared part as a starterkit plugin, keeps the personal part in
`ai-cli-config` under the `.local` marker, and adds the controls that keep personal tokens
out of the public repository: a token gate that runs before every push, and an explicit
export manifest instead of "everything that is not `.local`".

Done means: a clean profile with no `ai-cli-config` installs the starterkit plugins and runs
a plan, a backlog capture, and the commit-message hook end to end, and a second opinion that
fails open with a one-line message when no external client is configured; both
owner hosts keep working throughout, with no window in which a live session loses a skill,
a script or a hook; and every push to starterkit after Task 2 passed the gate.

### Task 2: Personal-token gate in `ai-cli-config`
- Description: add `scripts/public-gate.sh` and its data files
  `scripts/public-tokens.local.txt` (one extended regex per line, prefixed by its category,
  covering every category of the inventory; patterns are word-bounded, so a short name never
  matches inside a longer word such as "archive" or a package name) and
  `scripts/public-allow.local.txt` (path-glob plus pattern pairs). The allowlist starts with:
  the marketplace `owner` fields; every `plugin.json` `author.name`; the repository's own GitHub
  slug in `install.sh`, `README.md` and `templates/{go,flutter}/settings.json` (line 7); the
  name `ai-cli-config` under `.agents/plans/**`; the standard `~/.claude/AGENTS.md` and
  `~/.claude/settings.json` mentions; runtime state written as
  `${CLAUDE_CONFIG_DIR:-$HOME/.claude}/runtime-state/...`; the GitHub noreply address as commit
  identity. Modes:
  - `--tree <dir>` scans the files of `git ls-files` when `<dir>` is a git work tree (ignored
    files are not part of a push), and every regular file when it is not (an export `--stage`
    output);
  - `--range <rev-range> -C <repo>` scans, for every commit in the range: paths
    (`git log --no-renames --name-only`), added lines (`git log -p --text
    --diff-merges=first-parent`), author and committer identity and the message
    (`%an %ae %cn %ce %B`); also tag messages and the ref names given;
  - `--text <file>` scans a free-text file (PR title and body, squash message).
  A binary file under `plugins/core*/` fails unless allowlisted. `private-path` hits fail under
  `plugins/core*/` and warn elsewhere; after Task 6 they fail everywhere. The gate **fails
  closed**: a missing, unreadable or empty token file exits non-zero.
  Install it on every starterkit checkout on both hosts as an untracked `.git/hooks/pre-push`
  that reads the pre-push lines on stdin (`<local ref> <local sha> <remote ref> <remote sha>`)
  and, per line, scans `<remote sha>..<local sha>`, or `<local sha> --not --remotes=origin` for a
  new ref, plus both ref names; it refuses any tag push and refuses the push when
  `public-gate.sh` itself is missing. A deletion (`<local sha>` all zeros) is not scanned and
  passes; a `<remote sha>` missing locally is treated as a new ref. A test script
  `scripts/test-public-gate.sh` covers it.
- Acceptance Criteria:
  - the test script passes: one fixture per category is caught; a clean fixture passes; an
    allowlisted line passes; a short name inside a longer word passes; a hit only in a commit
    message, only in an author email, only in a path, only in a ref name, or only in a tag
    message is caught; a binary under `plugins/core/` fails; a missing or empty token file and a
    missing `public-gate.sh` make the hook refuse the push; a branch deletion passes; a push
    whose `<remote sha>` is missing locally is scanned as a new ref; `--tree` on a directory
    that is not a git work tree scans every regular file;
  - `--tree` on the starterkit tree after this plan's branch is merged (backlog
    261015.M.0003 consumed) reports only the known `pipeline` private paths
    (warnings) and nothing that fails;
  - the planted-token test pushes to a local bare repository (`git init --bare` in the
    scratchpad, added as a `file://` remote), never to `origin`, and is refused on both hosts;
  - the gate prints the category and location; the token list itself is never written
    into starterkit.
- Pitfalls & edge cases: pushed PR refs cannot be deleted, so the range mode covers every
  commit, not only the tip tree; `git push --no-verify` bypasses the hook, so the export
  script (Task 5) calls the gate itself as well; a token split across a line break or inside
  a URL must still match; the pre-push hook must handle several refs in one push.
- Complexity: Medium

### Task 5: Export script from `ai-cli-config` to starterkit
- Description: `scripts/starterkit-export.sh` with an explicit manifest
  `scripts/starterkit-export.manifest` mapping source paths to starterkit paths
  (`skills/<name>` → `plugins/core/skills/<name>`, the shared `bin/` files →
  `plugins/core/bin/`, `agents/code-standards-auditor.md` → `plugins/core/agents/`, the shared
  hooks → `plugins/core-hooks/hooks/`). One design, no state file in `ai-cli-config`:
  - **Source is a commit, never the working tree.** The script fetches and exports
    `origin/v<YYYYMM>` by default (pushed, therefore backed up), or `HEAD` when asked, and then
    refuses a dirty tree. Files come from `git archive`/`git show` of that commit, so `.env`,
    agent memory and caches never leave. The source SHA is written to
    `plugins/core/.export-source` in starterkit.
  - **Filters.** Skip a path one of whose segments is a `.local` marker: a file named
    `<name>.local.<ext>` or a directory named `<name>.local`. `~/.local/`, `$HOME/.local/`,
    `.env.local` and similar are not markers. Drop `SKILL.md` table rows that reference a
    marker path; any other marker reference in a shared file fails the run.
  - **Drift guard.** Before writing, re-export the SHA recorded in
    `origin/main:plugins/core/.export-source` using the script and manifest from that same SHA,
    and compare only the manifest-mapped paths with `origin/main` (`plugin.json` versions and
    `.export-source` are outside that scope). Any difference is a hand edit in starterkit: the run stops and shows
    the diff, to be brought back into `ai-cli-config` by hand first. First run (no
    `.export-source` on `main`): the guard is skipped and the run says so.
  - **One export in flight.** Refuse to run while any `export/*` branch exists on `origin`;
    branches are deleted at merge (`gh pr merge --squash --delete-branch`), and an abandoned
    one is deleted by the owner first. Branches are named
    `export/<YYYYMMDD>-<n>`, `<n>` the next free number for that day.
  - **Output.** In a starterkit worktree on the new branch, created from `--base <ref>`
    (default `origin/main`; Task 8 passes the Task 6 branch): copy, remove
    files that left the manifest, keep executable bits, bump the `version` of each changed
    plugin, commit, then run `public-gate.sh --tree` and `--range origin/main..HEAD` and
    `claude plugin validate` on each plugin. It never pushes.
  - **`--dry-run`** prints the file list and the diff against `origin/main` and writes nothing.
  - **`--stage <dir>`** writes the filtered copy to `<dir>` and touches no starterkit checkout.
  - **Cadence**, in the script header: export after each monthly rollover, and in the same PR
    as any `pipeline` change that needs a newer `core`. Before `gh pr create/edit/comment/merge`,
    run `public-gate.sh --text` on the title, body and squash message.
- Acceptance Criteria:
  - `scripts/test-starterkit-export.sh` passes against fixture repositories:
    - `x.local.md`, `scripts/y.local.sh` and a `z.local/` directory are skipped;
    - false-positive set exported unchanged: a file containing `~/.local/bin`,
      `$HOME/.local/bin` and `.env.local`, and a path `local/notes.md`;
    - a marker row is dropped and the rest of the table is byte-identical;
    - a marker reference in prose fails the run;
    - an untracked `.env` and an uncommitted edit are not exported;
    - a hand-edited file on the fixture `main` stops the run with its diff; the first run
      without `.export-source` passes and says the guard was skipped;
    - any `export/*` branch on the fixture remote refuses the run, including one whose PR was
      squash-merged without deleting the branch;
    - `--base` creates the branch from the given ref; the drift guard still compares with
      `origin/main`, using the manifest of the recorded SHA;
    - `--stage <dir>` writes only `<dir>` and leaves every starterkit checkout untouched;
    - a second run with no source change produces no commit; `--dry-run` writes nothing;
  - a `--dry-run` against the real trees lists exactly the inventory's shared and split files;
  - the script refuses to run when the starterkit checkout is dirty.
- Pitfalls & edge cases: starterkit-owned files (`plugin.json`, `hooks.json`, `README.md`,
  marketplace entry) are outside the manifest and never overwritten; the version bump changes
  `plugin.json`, which the drift guard must ignore; the drift guard needs the manifest as of
  the recorded SHA when a manifest line was added since.
- Complexity: Hard

## Risks

- A new personal token reaches the public repository; pushed PR refs cannot be deleted.
  Controls: the explicit manifest (default deny), the gate in the export, in pre-push on both
  hosts (fail closed, every pushed ref, identity, paths and messages) and on PR text, and
  categories instead of values in this plan. Names already in `main` history through PR #20
  are accepted as public; the gate does not undo history.
- The two copies drift (D1 = mirror): an edit made in starterkit is lost on the next export.
  Control: the drift guard re-exports the recorded source SHA and stops on any difference.
- A commit reaches a live session on the other host before what it depends on. Control:
  Task 4's commit order (wrappers, exposure, verification, then call sites), and Task 8 merges
  only after both hosts pass the smoke checks.
- A plugin user loses a key at the next version bump. Control: keys never live in the plugin
  cache (Task 4 step 5).
- Licence: `pdf` cannot be published (D8); other vendor material is checked the same way
  before it enters the manifest.
- Authority: Tasks 3–4 edit existing skills and scripts; instruction edits go through
  `skill-tuner`, script edits and the Linux `~/.local/bin` links wait for the owner's approval —
  the plan's pace depends on those approvals.

## Trade-offs

- Mirror over single copy (D1): two copies and an export script, in exchange for zero change
  to what the hosts load, unchanged `skill-tuner` routing, `.local` rows working as the owner
  defined them, and no public PR per remark. Reverse by enabling `core` on the hosts, deleting
  the bare skills and replacing the `settings.json` hook entries with `core-hooks`.
- An explicit export manifest over "everything that is not `.local`": a new shared skill needs
  a manifest line, but a forgotten `.local` suffix cannot publish a personal file. Reverse by
  generating the manifest from `git ls-files` minus marker paths.
- Drift guard by re-export of the recorded SHA over a state file in `ai-cli-config`: costs one
  extra export per run, but the record lives where the export lands, needs no commit after a
  merge, and an abandoned PR leaves nothing stale. Reverse by keeping per-file hashes in a
  committed state file.
- Command names on `PATH` through directories already on it, over a `settings.json` PATH
  change: needs links on each host, but no owner-only settings commit and no dependency on a
  restart. Reverse by adding the `bin/` directories to `env.PATH`.
- A separate `core-hooks` plugin (D7): one more marketplace entry, in exchange for paid,
  data-sharing hooks being opt-in. Reverse by moving `hooks/` into `core`.
