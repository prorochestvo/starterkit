# Task Breakdown

## Overview

`plugins/core/bin/second-opinion.sh` scans the material it is about to send to an external
reviewer and refuses on a credential-shaped string. For GitHub it only knows classic personal
tokens (`ghp_[A-Za-z0-9]{28,}`). OAuth (`gho_`), user-to-server (`ghu_`), installation
(`ghs_`), refresh (`ghr_`) and fine-grained (`github_pat_`) tokens pass the scan and can be
sent to a third-party model. GitHub also announced that installation tokens move to a new
stateless format of about 520 characters. So the pattern should not assume the classic
character set either.

## Assumptions

- The scan is a pre-send guard with an `--allow-secrets` override. A false positive costs one
  re-run, and a miss leaks a credential, so a wide pattern is the right default.
- The new installation-token character set is confirmed by the per-request override header
  in GitHub's changelog. The same check is planned in the hive repository (its redaction
  pattern has the same gap); one observation serves both.

## Tasks

### Task 1: Confirm the new token's character set (prerequisite)
- Description: obtain one new-format installation token with the documented override header
  and record only its length and character classes, never the token.
- Acceptance Criteria:
  - The plan records the observed length and character set, with the changelog link.
- Pitfalls & edge cases: the token is a live credential. Print nothing but its length and
  character classes.
- Complexity: Easy

### Task 2: Scan every GitHub token family
- Description: replace `-e 'ghp_[A-Za-z0-9]{28,}'` with
  `-e 'gh[pousr]_[A-Za-z0-9_.-]{16,}'` and add `-e 'github_pat_[A-Za-z0-9_]{16,}'`. Widen the
  class to the set Task 1 observes if it differs.
- Acceptance Criteria:
  - Material containing a sample of each family (synthetic, built in the test so the
    repository holds no credential-shaped literal) is refused, and the refusal names the
    line.
  - Material without tokens is sent unchanged.
  - The public gate is clean on the change.
- Pitfalls & edge cases:
  - Keep the samples out of the repository as literals. Assemble them at test time, the way
    `test-backupper.sh` does.
  - `grep -E` on macOS and GNU must both accept the pattern.
- Complexity: Easy

## Execution Order

1. Task 1
2. Task 2

## Risks

- A wider pattern refuses more material, for example documentation that shows a token
  prefix followed by a long identifier. The `--allow-secrets` override covers that case.

## Trade-offs

- Task 2 can ship before Task 1. The default class already covers the likely new
  characters, and Task 1 only confirms it. Reversal: revert the pattern change.
