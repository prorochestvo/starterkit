## Overview

The shared agent tooling lives in the private `ai-cli-config` (`~/.claude` on both owner
hosts). This plan moves it into starterkit as the plugins `core` and `core-hooks`: one copy,
reviewed and merged like code. What stays in `~/.claude` is private; what is in starterkit is
public.

Done means: a clean profile runs a plan, a backlog capture, the commit hook and a fail-open
second opinion from the plugins; both hosts load all shared parts from starterkit only; no name
exists twice; no live session lost a skill or hook; every step had a rollback; every public push
and text passed the gate.

## Risks

- **A personal fact reaches starterkit.** Controls: D3, the fail-closed pre-push on every clone
  (new ones via the template), `--text` on all public GitHub text, the D6 owner review for
  prose. The gate is client-side: `--no-verify`, a hooks-path override and API writes bypass
  it, and push protection covers credentials only (owner items).
- **A name collision shadows a public skill or agent.** A4 on commit, restore and cut-over.
- **Between Tasks 13 and 14 both copies are listed**: bare names load the frozen personal copy
  and `core:*` stays unused; the window is the drain only.
- **The served checkout is an executable trust root**: any session can edit
  `plugins/core-hooks/hooks/*`, as with `~/.claude/hooks` today. Accepted; it stays on `main`
  or a branch of it, other work in worktrees.
- **A session loses a skill or hook.** Personal copies win until Task 14; Q1, Q8, the drain.
- **Mac `pipeline` pins jump to the served tree** (Q4); accepted. **Keys** stay out of plugins.

## Trade-offs

- **Location over markers (D2).** No wire script; a skill with personal facts splits in two.
  Reverse: merge the split back.
- **Single copy (D1).** Every public-skill edit is a public PR. Reverse: revert Task 14 and the
  flip, switch the marketplace back, revive `7c68f5f`.
- **Linux by hand (D5).** It lags `main` until updated.
- **No history import**; B1 names `F`.
