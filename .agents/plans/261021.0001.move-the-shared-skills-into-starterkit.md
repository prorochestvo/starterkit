## Overview

The owner's shared agent tooling (skills, helper scripts, hooks) lives only in the private
repository `ai-cli-config`, checked out as `~/.claude` on both of the owner's hosts. A new
machine or a new person cannot start from it, and the public `pipeline` plugin already
depends on it.

This plan moves the shared part into starterkit as the plugins `core` and `core-hooks`, where
it lives as code in **one copy**: versioned, reviewed by PR and merged like any other code.
Each owner host serves starterkit as a local directory marketplace: the Mac serves its working
checkout (edits are live in the next session), the Linux agent account serves a clone that
only fast-forwards to `main` (only merged work runs there). `~/.claude` keeps the personal
part: personal skills, personal hooks and helpers, settings, and the `.local` overlays of the
shared skills, which stay next to their skill in the served checkout but are git-ignored there.

Done means: a clean profile with no `ai-cli-config` installs the starterkit plugins and runs
a plan, a backlog capture, and the commit-message hook end to end, and a second opinion that
fails open with a one-line message when no external client is configured; both owner hosts
load every shared skill, helper and hook from starterkit and none from `~/.claude`; no live
session on either host lost a skill, a script or a hook at any moment of the cut-over; every
cut-over step had a stated rollback; and every push to starterkit after Task 2 passed the gate.

## Risks

- **A personal token reaches the public repository.** Pushed PR refs cannot be deleted, and
  under D3 every remark becomes a public push. Controls: the pre-push gate on every starterkit
  clone (fail closed, every pushed ref, identity, paths and messages), `--text` on PR text and
  squash messages, overlays git-ignored by pattern, and categories instead of values here.
- **A `.local` overlay is committed by force** (`git add -f`). It is then tracked and scanned
  by the gate, which catches tokens but not personal prose without tokens. Control: B1's
  acceptance check and a `git ls-files | grep -E '\.local(\.|/)'` step in the gate's tree mode
  is a candidate follow-up.
- **The Mac serves an unmerged working tree.** A branch switch, a rebase in progress or a
  half-edited skill in the served checkout changes every new Mac session. Controls: D11 (plan
  and PR work in worktrees; the served checkout on `main` or a working branch based on it);
  `starterkit-wire.sh` refuses a checkout mid-rebase.
- **A session loses a skill or a hook during the cut-over.** Controls: personal copies win the
  bare name until Task 14; the flip enables only plugins installed on both hosts; old sessions
  keep their start-of-session hook set (Task 7 Q1) and their files until the drain; every step
  has a rollback.
- **Project-scoped `pipeline` pins jump to the served tree at the switch** (Task 12 step 3).
  Old projects pinned at `1.0.0`–`1.15.0` start reading current `main`. Control: Task 7 Q4 and
  a `pipeline:new-plan` run per pinned version; this is also a fix, since the pins were stale.
- **Linux runs behind `main`.** The served clone fast-forwards daily; a failed fast-forward
  (a local change in the clone) leaves it stale silently. Control: push URL disabled, no work
  in that clone, `--check` in the crontab line.
- **A plugin user loses a key at a version bump.** Keys never live in the plugin (Task 4).
- **Licence:** `pdf.local` stays private (D8); other vendor material is checked before a PR.
- **Authority and pace:** instruction edits go through `skill-tuner`, scripts and the Linux
  `~/.local/bin` and crontab changes wait for the owner's approval, `settings.json` is
  owner-applied, and the drain depends on session restarts.

## Trade-offs

- **Single copy over mirror (D1, owner decision).** One copy, reviewed like code, and no
  export, drift guard or batch publishing; in exchange every shared-skill edit becomes a public
  PR, the hosts' load path changes, and the cut-over needs Tasks 7–14. Reverse by restoring the
  personal copies (revert Task 14), reverting the flip, switching the marketplace back to
  GitHub, and reviving the export script from `7c68f5f`.
- **Overlays linked from `ai-cli-config` over copied by the engine (D10).** One copy per
  overlay that travels with the existing engine and commit flow, in exchange for symlinks in the
  served checkouts and a wire script. Reverse by replacing each link with the file and adding
  a `sync.sh` collection step.
- **A dedicated Linux served clone over the development clone (D11).** Only merged work runs,
  agents keep their branches, in exchange for a second clone and a crontab entry.
- **No history import into starterkit.** The files' history before `F` holds personal tokens
  that the gate would refuse, and a filtered rewrite would publish old personal decisions;
  `ai-cli-config` keeps that history privately and each move commit names `F`. Reverse: not
  needed; `git log` in `ai-cli-config` remains the record.
- **One settings flip over staged enables.** One owner-applied commit, one moment per host,
  in exchange for depending on Task 7 Q1; the two-commit variant with the dedupe guard is the
  fallback.
- **The `pipeline` dependency deferred to Task 15.** Removes an unverified state (dependency
  installed but disabled) from the cut-over, in exchange for public users of `pipeline 1.16.0`
  installing `core` by hand for a short time, which the README states.
- **The manifest kept as the move list.** One authoritative list for the copy and the
  deletion, deleted with the moved paths.
